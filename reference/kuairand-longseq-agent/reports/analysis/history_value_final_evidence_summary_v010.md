# 历史是否有用：Validation、sealed test 与 random audit 最终证据总结 v010

生成日期：2026-08-23（Asia/Shanghai）  
最终执行合同 SHA-256：`a73b254c43de31be6d9490a7b33398f77cf7fd49e7b0624c931886beca8fea04`

## 一、最终答案

在冻结的 GPU Adam 协议（learning rate `0.03`、`100` steps）下，给相同静态模型增加严格时点用户历史，能够稳定提高离线排序和用户内区分能力。该历史增量依次通过了 Validation、时间外 sealed standard test 和正式 random exposure audit：

| 阶段 | 主分析行数 | ΔAP（95% CI） | Δevent-gAUC（95% CI） | Δlog-loss（95% CI） | ΔBrier（95% CI） | 判定 |
|---|---:|---:|---:|---:|---:|---|
| Validation | 886,452 | +0.035626 [0.031302, 0.040028] | +0.038450 [0.034904, 0.041906] | -0.021001 [-0.022926, -0.019150] | -0.008278 [-0.009120, -0.007494] | pass |
| sealed standard | 4,401,690 | +0.040651 [0.036937, 0.044402] | +0.046205 [0.043415, 0.049011] | -0.023128 [-0.024797, -0.021537] | -0.009028 [-0.009722, -0.008372] | pass |
| random exposure | 42,372 | +0.026188 [0.018296, 0.034667] | +0.059032 [0.044595, 0.073569] | -0.009589 [-0.019104, 0.000062] | -0.001654 [-0.005735, 0.002461] | pass |

这里的增量均为 `ADAM_BL2 − ADAM_BL1`，在相同目标行、相同静态特征、相同优化器和相同训练协议下比较。正的 AP/gAUC 与负的 log-loss/Brier 表示历史模型更好。

可支持的结论是：**当前 H2 用户总体历史特征包具有可复现的预测价值，而且排序价值能够迁移到 random exposure。** 不能据此声称线上因果收益，也不能声称 SGD 或其他优化器同样成立。

## 二、数据来源与实验背景

正式数据来自 KuaiRand governed Silver snapshot：

- `events_early_standard.parquet`：早期标准曝光；
- `events_late_standard.parquet`：后期标准曝光；
- `events_random.parquet`：正式随机曝光；
- `videos_basic.parquet`：视频、作者、音乐、标签、时长、上传时间及画面几何等静态元数据；
- `label_formula_mismatch_rows.parquet`：只回补官方 `long_view` 公式不一致而隔离的正式行。

目标标签为正式 `long_view`。标准阶段目标限制为 `tab=1`；random 阶段使用 2022-04-22 至 2022-05-08 的全部正式 random exposures。random canonical union 为 `42,982` 条主 Silver 行加 `45` 条官方公式不一致回补行，共 `43,027` 行、`3,621` 个正例、`1,000` 个用户，正例率 `0.084156`。

random 数据包含 `11,141` 行此前未在标准行为中出现的视频，但 `videos_basic` 静态元数据缺失为 `0`。正式 random 特征审计结果为：目标身份唯一、视频连接缺失 `0`、严格时点违规 `0`、窗口单调性违规 `0`、正例计数违规 `0`。

## 三、模型与历史特征定义

- `BL0`：冻结的常数概率基线；
- `ADAM_BL1`：静态特征基线，包括用户、视频、作者、音乐、视频/上传/音乐类型、标签组合、时长桶等类别特征，以及时长、上传年龄、宽高、长宽比和缺失/有效性标志；
- `ADAM_BL2`：与 BL1 完全相同，再加入 H2 用户总体历史。

H2 包含 lifetime 与最近 `10/50/200` 个用户批次的事件数、正例数、平滑 long-view rate，另含历史批次数、距最近历史批次时间、是否有历史和各窗口是否充足。比例特征采用训练期正例率及强度 `20` 的平滑先验。

标准目标的历史要求 `history_time_ms < target_time_ms`。random 特征使用独立构造器，只允许 standard events 更新历史，并通过 ASOF 条件 `random_time_ms > standard_state_time_ms` 连接；任何 random 标签都不能进入自身或其他 random 行的历史。

这项实验检验的是“整套 H2 是否有用”，不是 10、50、200 窗口的相互消融，也不检验用户×标签历史 H3。因此不能把结果解释为某个单一历史窗口最优，也不能直接用于“用户喜欢哪些标签”的个性化标签结论。

## 四、顺序审查设计与统计含义

实验严格按 `Validation → sealed test → random audit` 顺序释放。每一阶段都在合同哈希、输入哈希与前置阶段制品哈希验证后运行。

主分析为 warm users 上的同一行配对比较。置信区间来自 `2,000` 次用户簇 bootstrap：以用户为重采样单位，保留同一用户内部曝光相关性。三个阶段所有主指标均有 `2,000/2,000` 个有效 replicate。

预注册历史门要求：

1. ΔAP 点估计至少 `+0.005`；
2. ΔAP 95% CI 下界大于 `0`；
3. Δevent-gAUC 点估计不低于 `0`；
4. Δlog-loss 与 ΔBrier 点估计不高于 `0`；
5. 学习模型概率有限且不存在大面积 `≤1e-6` 或 `≥1−1e-6` 饱和。

random 的 ΔAP 为预注册最小效应 `0.005` 的约 `5.24` 倍，95% CI 完全在零以上；Δevent-gAUC 的区间也完全为正。random 的 log-loss/Brier 点估计方向改善，但其区间跨过零，因此这两项只能表述为“方向符合预注册门、尚无 95% 显著性”，不能表述为 random 概率损失已被确定改善。

三个阶段不可简单合并成一个总置信区间：sealed 与 random 覆盖相同日期且用户可能重叠，阶段间不是独立样本。这里强调的是按合同连续复现与跨曝光迁移，而不是事后 meta-analysis。

## 五、分阶段结果与分析

### 5.1 Validation：首次可证伪确认

目标为 2022-04-18 至 04-21 的 `886,452` 条标准曝光。训练窗为 04-08 至 04-16，04-17 只用于校准。

- ΔAP `+0.035626`，95% CI `[0.031302, 0.040028]`；
- 四天均为正向，达到 `4/4`；
- 静态基线、绝对概率、历史增量与概率健康门全部通过；
- BL1 相对 BL0 的 ΔAP 为 `+0.228447`，95% CI `[0.214740, 0.242174]`，证明历史增量不是建立在失效静态基线上。

### 5.2 sealed standard：时间外稳定性

目标为 2022-04-22 至 05-08 的 `4,431,299` 条标准曝光，主分析 warm users 为 `4,401,690` 行。训练窗为 04-08 至 04-20，04-21 只用于校准。

- ΔAP `+0.040651`，95% CI `[0.036937, 0.044402]`；
- 17 天全部为正向，达到 `17/17`；
- 四个主要增量指标方向一致且区间均排除零；
- 静态、绝对概率、历史和概率健康门全部通过。

Validation 与 sealed 的效应量相近且 sealed 没有衰减，但合同没有阶段间差值检验，不能声称 sealed 显著强于 Validation。

### 5.3 random audit：曝光分布迁移

random 全部目标为 `43,027` 行，主分析 warm users 为 `42,372` 行、`983` 个用户、`3,558` 个正例。

- ΔAP `+0.026188`，95% CI `[0.018296, 0.034667]`；
- Δevent-gAUC `+0.059032`，95% CI `[0.044595, 0.073569]`；
- Δlog-loss `-0.009589`，95% CI `[-0.019104, 0.000062]`；
- ΔBrier `-0.001654`，95% CI `[-0.005735, 0.002461]`；
- 逐日 AP 为 `14/17` 天正向，负向日期为 04-23、04-27 和 05-02；日均 ΔAP `+0.023077`，最小 `-0.009538`，最大 `+0.055458`；
- BL1/BL2 概率均全部有限，极端饱和比例为 `0`。

因此 random 的历史迁移门和概率健康门通过，最终阶段为 `pass`。相比标准曝光，random 的 pooled ΔAP 略小但仍显著超过 SESOI；event-gAUC 增量反而更大。没有预注册跨阶段差值检验，所以只能称为“迁移后仍保持实质正向”，不能声称不同曝光域效应存在显著差异。

## 六、必须单独解释的 random 校准问题

random 正例率约 `8.4%`，远低于标准阶段约 `31.5%–32.1%`。sealed 上冻结的概率校准器没有适应这次 exposure/prevalence shift：

| random warm 模型 | AP | event-gAUC | log-loss | Brier | ECE20 |
|---|---:|---:|---:|---:|---:|
| BL0 | 0.083971 | 0.500000 | 0.448396 | 0.132386 | 0.235512 |
| ADAM_BL1 | 0.170240 | 0.556485 | 0.516692 | 0.169610 | 0.293838 |
| ADAM_BL2 | 0.196428 | 0.615517 | 0.507102 | 0.167955 | 0.282172 |

BL1 相对 BL0 的 AP `+0.086270`，95% CI `[0.074311, 0.098777]`，event-gAUC 也增加 `+0.056485`；所以静态模型仍有明显排序价值。但 BL1 的 log-loss `+0.068295`、Brier `+0.037224`，绝对概率门失败。BL2 相比 BL1 缓解了一部分损失和 ECE，却仍没有超过 BL0 的绝对概率损失。

这意味着：

- **“历史是否有排序价值”通过；**
- **“sealed 校准概率能否原样部署到 random 域”不通过。**

CPU Agent 可以使用 BL2 score 进行候选排序或相对比较，但若需要把输出解释为真实 long-view 概率，必须用独立、合法的部署域校准集重新校准，并把这一步与本次封存审计区分开。不能用 random audit 标签事后调参后仍宣称本次 random 是 untouched 审计。

## 七、切片证据与风险点

random 中 `history_200_plus` 有 `41,771` 行，占全部目标约 `97.1%`；该组 BL2 相对 BL1 的 ΔAP 为 `+0.026031`、Δlog-loss 为 `-0.014997`，与 pooled 结论一致。`history_500_plus` 探索切片为 `37,297` 行，ΔAP `+0.027252`、Δlog-loss `-0.027870`。

低历史深度切片很小：`history_0_49` 仅 `133` 行、`14` 个正例，`history_50_199` 仅 `1,123` 行。它们的 AP 点估计提高，但 log-loss 变差，且没有切片级 bootstrap CI；不可据此推广低历史用户的概率效果。

行为冷视频 `12,966` 行上，BL2 相比 BL1 的 AP 从 `0.133759` 升至 `0.165196`，说明排序增量并不只存在于 warm videos。另一方面，`video_duration_invalid` 仅 `1,310` 行、`23` 个正例，BL2 AP 低于 BL1（`0.096013` vs `0.147327`）；该小切片应作为上线监控项，而不是用 pooled 结果掩盖。

上述切片均为描述性点估计，不替代主分析用户簇置信区间，也不支持在切片之间作显著性排序。

## 八、优化器、硬件与数值复现

正式模型使用 conda `Kuai` 环境、PyTorch `2.11.0+cu128`、RTX 5070 Ti。Adam 配置为 learning rate `0.03`、`100` steps。sealed 重建时 BL1/BL2 的 GPU 正则化目标 regret 分别为 `0.000420` 和 `0.000484`，低于允许值 `0.002774` 和 `0.002646`，两条充分性检查均通过。

v009 在 random 打开前因跨进程逐概率容差 `1e-9` 过严而停止。随后 sealed-only 诊断比较全部 `4,431,299` 行：BL1/BL2 概率最大漂移分别为 `1.59e-7` 和 `5.14e-7`，最大指标复现误差为 `7.59e-8`，相关系数约为 `1`。v010 按 SHA-256 加载该冻结模型，不再重训或校准，然后才打开 random。

SGD 按项目决定冻结。当前结论只属于 GPU Adam，不能声称优化器稳健性。未来探究 SGD 失败原因时应建立独立合同，不应回写或覆盖本次主实验。

## 九、给 CPU Agent 系统集成的证据指导

1. 保留 BL1 静态路径作为基线与缺历史回退；在严格历史可用时使用 BL2 ranking score。
2. CPU 端必须逐字段复现静态预处理、类别编码、H2 的 lifetime/10/50/200 窗口、平滑先验及 scaler；尤其保证同 timestamp 批次不会互相泄漏标签。
3. random/在线目标只能读取目标时刻之前的 standard/已授权历史。禁止让当前目标标签或同批次结果进入历史状态。
4. 若 Agent 只做排序，可优先集成 BL2 raw/calibrated monotone score；若输出概率，先建立独立部署域校准与校准监控，不能直接采用本次 sealed 概率。
5. 上线监控至少按 exposure domain、历史深度、warm/cold video、duration-valid 状态记录 AP/排序代理指标与校准指标。重点观察低历史和 duration-invalid 小切片。
6. 当前 H2 是用户总体 long-view 历史，不含用户×标签偏好；如要预测“用户喜欢哪些标签”，应另建 H3 合同，以 BL2 为固定基线做用户×标签历史增量实验。
