## 1. 结论先行

本研究不试图复现一个可上线的推荐系统，而是回答一个受控的离线问题：

> 在候选视频曝光的那一刻，只用当时已可见的用户历史、用户静态信息和视频基础元数据，
> 能否更好地预测这次曝光的官方 `long_view` 标签？

答案是能，但每一条结论都有硬边界：

| 层级 | 已验证的事实 | 不可越过的边界 |
|---|---|---|
| **v010　历史价值** | 冻结 GPU Adam 协议下，加入 H2 严格用户历史的 BL2 相比同静态特征的 BL1，在 Validation、后置 standard 与 random 曝光审计上 AP 增量均显著为正 | 是**离线排序**增量；不代表线上因果收益，也不代表换优化器仍成立 |
| **v011　概率校准** | 目标域截距校准显著降低 Log Loss / Brier，且**严格保持排序不变** | 是 post-audit 的时间外测试，不是全新的确认试验 |
| **v012　受约束适配** | 成对目标域重训练在最终回放上同时提升排序和概率损失，优于 `OLD_BL2 + v011` | 同样是 post-audit；上线前仍需新数据确认与人工审批 |

<a id="fig1"></a>

![四个证据阶段的 ΔAP 与 95% CI](figures/fig1_delta_ap_forest.png)

**图 1** 是本研究的主结果。上组三行是同一个对比（`ADAM_BL2 − ADAM_BL1`），
覆盖三个逐步开放的数据域；下组一行是**另一个对比**（`NEW_BL2 − OLD_BL2+v011`），
回答的是"重训练还值不值"。**两组不能相加，也不能串成一条链**——理由见 [§7.1](#7-1)。

三件值得单独记住的事：

1. **方向一致。** 四个 95% CI 的下界都大于 0，且都超过预注册的最小效应 0.005。
2. **random 域的区间最宽。** 它只有 42,372 行，宽度是样本量的直接后果，不是效应变弱。
3. **random 域的绝对概率不合格。** 排序迁移过去了，概率刻度没有——这正是 v011 存在的理由。

最精炼的表述是：**在本任务、冻结特征、严格时点规则与 GPU Adam 协议下，
H2 用户历史有可复现的离线排序价值；目标域校准与受约束适配带来工程价值，
但尚不构成线上或因果证明。**

## 2. 数据与访问顺序

> 这一章回答：数据长什么样、为什么这样切、以及"切分有没有被重复使用"。

### 2.1 原始数据

KuaiRand-1K 从更大版本抽取 1,000 名用户，同时提供标准推荐日志与插入的随机曝光。
选它而不是更小的 Pure 版本，是因为问题依赖完整、严格按时间排序的行为史。

| 数据域 | Raw 行数 | Silver 行数 | 在研究中的角色 |
|---|---:|---:|---|
| early standard（04-08 → 04-21） | 5,055,984 | 4,992,443 | Train + Validation |
| late standard（04-22 → 05-08） | 6,657,061 | 6,556,501 | sealed 时间外测试 |
| random exposure（04-22 → 05-08） | 43,028 | 42,982 | 独立曝光审计 |
| users / videos basic | 1,000 / 4,371,868 | 不变 | 静态维表 |

`video_features_statistic_1k.csv`（52 列月内聚合统计）**默认禁止进入同月预测**——
读它相当于把目标期之后的信息带回当前事件。它从未物化进 Silver，也从未 join。

Silver 清洗不是删行：完全重复行保留一条 canonical、副本进审计；载荷冲突整组进 quarantine；
`long_view` 公式不一致的记录单独隔离并**同时保留官方标签与重算值**。
每种问题行都有去向，没有一种"清干净了就消失"。

### 2.2 访问顺序与切分对齐

<a id="fig4"></a>

![数据域、访问顺序与实验切分时间轴](figures/fig4_data_timeline.png)

**图 2** 是这份研究在方法上最值得说的一处设计，也是最容易被质疑的一处。

质疑通常是："v012 是不是换了个切法，把对自己有利的数据切出来了？"答案可以逐行核对：

```text
random 域 canonical 总量                                    43,027 行
├─ 前置区间 04-22 → 05-02                                    19,275 行
│    v011:  fit 8,731 + selection 10,544                  = 19,275
│    v012:  adaptation 11,999 + calibration 7,276         = 19,275   ← 边界完全相同
└─ 后置区间 05-03 → 05-08                                    23,752 行
     v011:  held-out test                                 = 23,752
     v012:  selection 11,353 + final replay 12,399        = 23,752   ← 同一区间的再切分
```

由此得到两个可核验的性质：

- **信息量对等。** v011 校准器所用数据与 v012 适配+校准所用数据在时间上同界，
  两个候选看到的历史信息完全相同。§6.3 的对比因此是公平对照，不是"新模型多看了几天"。
- **最终回放从未参与选择。** 05-06 → 05-08 的 12,399 行在 v011 报告之后才被单独切出；
  v012 的 C1/C2/C3 选择只用 05-03 → 05-05 的 11,353 行。

它的代价也必须写出来：v012 的 selection 段取自 v011 曾报告过的 held-out 区间。
这在时序上完全合法（v011 早已冻结发布），但意味着**两轮结果共享数据、不可当作两份独立证据相加**。

**还有一个硬约束：random 域的 43,027 行已被 100% 消耗**，包内没有剩余的随机曝光数据。
这直接决定了"待新数据确认"该怎么做——见 [§8](#8)。

## 3. 模型与时点规则

> 这一章回答：三个模型差在哪、"严格历史"到底怎么定义、防泄漏靠什么保证。

### 3.1 三个嵌套模型

三个模型预测同一批候选事件的 `long_view`，**只改变允许使用的信息**：

| 模型 | 组成 | 这个对比回答什么 |
|---|---|---|
| **BL0** | 冻结的常数概率 $\hat p_i = \hat\pi_{\mathrm{train}}$ | 只报训练期总体正例率时，概率损失的基础参照 |
| **BL1** | 静态特征的正则化稀疏逻辑回归（9 个类别 + 5 个连续 + 5 个质量状态，共 19 个字段组） | 静态 ID、元数据和质量状态本身能解释多少 |
| **BL2** | $\mathbf{x}^{(\mathrm{BL2})}_i=[\mathbf{x}^{(\mathrm{BL1})}_i,\ \mathbf{h}_u(t_i)]$ | **严格用户历史是否在同一静态模型之上带来增量** |

BL1 与 BL2 的**唯一系统差异**是那 18 维历史特征（展开后 13,527 → 13,545 列），
所以差异可归因于历史，而不是换了数据行、标签或静态特征。

对 BL1/BL2，线性分数与概率为 $s_i=\mathbf{x}_i^\top\mathbf{w}+b$、
$\hat p_i=\sigma(s_i)=1/(1+e^{-s_i})$，训练目标是带 L2 的二元交叉熵，$\alpha=10^{-4}$，
截距不参与正则。

### 3.2 严格历史：唯一允许的边界是 $t_j < t_i$

对用户 $u$ 在目标时刻 $t_i$，允许的历史集合是

$$\mathcal H_u(t_i)=\{\,j:\ u_j=u,\ t_j<t_i\,\}.$$

**严格不等式是本项目的核心反泄漏约束。** 对相同 `(user_id, time_ms)` 的多个候选，
执行顺序必须是：

```text
读取目标时间戳批次
  → 用此前已冻结的用户状态，为批内每个候选构造同一份历史特征
  → 预测并保存
  → 才用该批次的已观测反馈更新用户状态
```

因此批内视频共享用户状态，却绝不能互相看到当前批次的标签、播放时长或点击。
对 random 目标，状态表**只含 standard 事件**——random 标签不更新任何 H2 特征。

H2 共 18 维：最近 10 / 50 / 200 个历史批次各 4 维（事件数、正例数、平滑正例率、窗口满标记），
加全历史 5 维与冷启动标记 1 维。平滑正例率为

$$R_{u,t}^{(k)}=\frac{P_{u,t}^{(k)}+\lambda\hat\pi_{\mathrm{train}}}{E_{u,t}^{(k)}+\lambda},\qquad \lambda=20 .$$

$\lambda=20$ 是**预先固定的收缩常量**，不是调出来的超参数：$E=0$ 时 $R$ 退回训练期先验，
$E=20$ 时数据与先验各占一半。它没有在任何后置数据上搜索过。

> **H2 只是用户总体历史状态**，不含 `user × tag`、`user × author` 或候选内容交互。
> 因此 BL2 的成功支持"历史有信息"，**不支持"用户偏好某类内容"**——后者需要另建 H3 合同。

### 3.3 一个必须说明的前提

v010 保存了特征、预测、指标与 manifest，但**没有把训练完的模型权重写成文件**。
后文 v011 / v012 所说的"从 sealed 暖启动"，实际加载的是事后从封存特征重新拟合复原的状态
（`reconstructed_frozen_model_state.npz`，SHA-256 `c36c6bec…`）。

重建质量：概率的平均绝对差 $1.4\times10^{-8}$、最大差 $5.1\times10^{-7}$、相关系数 1。
差异在 float32 容差之内，对任何指标的任何一位有效数字都不可见，**结论不受影响**。

写出来是因为：这次能补救，是因为特征矩阵恰好被保留了。
**后续合同应把"模型权重必须落盘并进 artifact manifest"列为硬性输出要求。**

## 4. 怎么读这些数字

> 这一章回答：每个指标衡量什么、95% CI 是怎么算的、什么话不能从它推出来。

### 4.1 四个指标各管一件事

$\Delta$ 一律是"候选模型 − 基线模型"，因此 AP / gAUC 为正较好，Log Loss / Brier 为负较好。

| 指标 | 它回答什么 | 常见误读 |
|---|---|---|
| **AP** | 全部事件按分数排序后，正例是否集中在前部（主排序指标） | 受正例率影响，不能跨 prevalence 差异很大的切片裸比 |
| **event-gAUC** | **同一用户内**正例是否通常得分高于负例，防止提升全来自用户间基础率差异 | 不等于线上曝光 slate 的排序表现 |
| **Log Loss** | 概率是否既正确又不过度自信（高置信错误重罚） | AP 好不保证 Log Loss 好——[§5.2](#5-2) 就是反例 |
| **Brier** | 预测概率离 0/1 标签的平方距离 | 与 Log Loss 相关但不等价，应同时报告 |

用 event-gAUC 而不是只看 pooled AP，是因为 Train 的 event-micro 正例率是 31.8944%，
而 user-macro 平均率是 39.55%——**相差 7.65 个百分点**，活跃用户的权重足以改变总体判断。

### 4.2 95% CI 来自 2,000 次配对用户簇 bootstrap

它不是"95% 的单次预测会落在区间内"，而是：

1. 以**用户**（不是单条事件）为重采样单位，保留同一用户内事件的相关性；
2. 每个 bootstrap 样本上**同时重算 BL1 与 BL2**，取同一批用户上的模型差值；
3. 取 2,000 个差值的 2.5% 与 97.5% 分位数。

所以"CI 不跨 0"只说明该**指定阶段、指定对比**下差异稳定，
不自动等价于跨域、线上或因果有效。

### 4.3 关于多重比较

**本项目所有 95% CI 均为 per-comparison 区间，未做 FWER / FDR 校正。**
v010 涉及 3 阶段 × 4 指标，v011 涉及 3 个校准族，v012 涉及 3 个候选配置 × 7 个门。

项目对多重比较的控制手段是**预注册**——主指标、最小效应量、判据与选择规则在看到结果前
已写入合同并冻结，而不是事后从多个结果里挑显著的。这在设计上有效，但不等价于统计校正。
因此对 CI 下界贴近 0 的对比（如 v012 的 $\Delta$Brier 下界 $-0.0003$），
应按"单次预设检验的边缘证据"读。

## 5. 两次预实验：为什么是 Adam，为什么先失败一次

> 这一章回答：优化器怎么选的、以及一次"看起来很好"的早期结果为什么被拦下来了。

<a id="5-1"></a>

### 5.1 先证明"优化得够充分"，再比较科学结果

Adam / SGD 的比较**只在 Train-only 上进行**，没有用任何后置标签。
方法是拿 CPU-LBFGS 求同一凸目标的高精度参考解 $\mathcal L_{\mathrm{reference}}$，
要求 GPU 优化器满足

$$\text{regret}=\mathcal L_{\mathrm{GPU}}-\mathcal L_{\mathrm{reference}}\ \le\ \max\!\left(10^{-4},\ 0.005\,\lvert\mathcal L_{\mathrm{reference}}\rvert\right).$$

这里的 regret 是**优化目标缺口**，不是用户体验 regret，也不是强化学习 regret，
更不是 BL2 相对 BL1 的指标差。

| 优化器路线 | 冻结配置 | 通过 / 6 probes | 最大 regret | 决策 |
|---|---|---:|---:|---|
| GPU Adam | $\eta=0.03$，30 steps | 0 / 6 | 0.006750 | 不足 |
| **GPU Adam** | **$\eta=0.03$，100 steps** | **6 / 6** | **0.000540** | **选中（最小充分 checkpoint）** |
| GPU Adam | $\eta=0.03$，300 / 1,000 steps | 6 / 6 | 0.000218 / 0.000040 | 更优但无理由超出预定 |
| 全批 SGD，momentum=0 | $\eta\in[0.001, 0.1]$，≤3,000 steps | 0 / 6 | 0.034773 | **冻结，不进入后置评估** |

最好的冻结 SGD（$\eta=0.1$，3,000 steps）的 BL1 regret 是允许值的约 **12.7 倍**。
把它带进 Validation，会把"历史带来什么"和"两个模型根本没被同等优化"混在一起。

> **"排除 SGD"不等于 SGD 证明历史无用**，也不等于 Adam 科学上更优。
> 它只说明原冻结 SGD 协议没达到进入后置评估的数值充分性。此后所有主张限定为 **GPU Adam 下**。

<a id="5-2"></a>

### 5.2 Gate 2B：有排序信号，但概率失败拦下了错误晋级

正式 GPU 验证前，Gate 2B 做了 7 天 Train rolling-origin 固定行回测：

| 模型 | AP | user-gAUC | Log Loss | Brier |
|---|---:|---:|---:|---:|
| BL0 常数概率 | 0.3249 | 0.4984 | **0.6274** | **0.2178** |
| BL1 静态基线 | 0.3248 | 0.5019 | 5.1621 | 0.3203 |
| BL2 = BL1 + H2 | **0.4357** | **0.5239** | 4.2696 | 0.2758 |

`BL2 − BL1` 的 $\Delta\mathrm{AP}=+0.1108\ [0.1015, 0.1204]$，7/7 天为正——排序信号很强。
**但 BL1 / BL2 的绝对概率损失比"只报平均值"的 BL0 差了一个数量级**，大量预测被裁剪在极端区间。

这个结果保留了"严格历史值得在健康协议下继续检验"的动机，
却**拒绝**把它升级为概率模型、序列模型或 Validation 结论。
后面三轮实验必须显式报告绝对概率门、概率健康、逐日稳定性与配对不确定性——
根源就在这一步。

## 6. 三轮正式实验

> 这一章回答：每轮问了什么、冻结了什么、只改变了什么、结论到哪为止。

```text
Train-only 粗筛与优化器充分性
      ↓（Adam 冻结；Validation 解锁）
v010：H2 是否有离线排序增量？
      ↓（发现 random 域基准率迁移：31.9% → 8.4%）
v011：冻结的排序在目标域能否得到可信概率？
      ↓（校准后仍需检验受限适配的价值）
v012：小幅、可回滚的目标域重训练能否再改善？
```

### 6.1 v010：H2 历史价值的三阶段确认

数据按 Validation → sealed standard → random audit 顺序开放，
每一阶段完成并哈希复核后才解锁下一阶段。主分析用同目标行的 warm users，
2,000 次配对用户簇 bootstrap 估计 CI（结果即[图 1](#fig1)上组）。

| 阶段 | 行数 / 用户 | $\Delta$AP | $\Delta$event-gAUC | $\Delta$Log Loss | $\Delta$Brier | 逐日 |
|---|---|---|---|---|---|---|
| Validation | 886,452 / 902 | +0.0356<br>[0.0313, 0.0400] | +0.0385<br>[0.0349, 0.0419] | −0.0210<br>[−0.0229, −0.0191] | −0.0083<br>[−0.0091, −0.0075] | 4/4 |
| sealed standard | 4,401,690 / 974 | +0.0407<br>[0.0369, 0.0444] | +0.0462<br>[0.0434, 0.0490] | −0.0231<br>[−0.0248, −0.0215] | −0.0090<br>[−0.0097, −0.0084] | 17/17 |
| random audit | 42,372 / 983 | +0.0262<br>[0.0183, 0.0347] | +0.0590<br>[0.0446, 0.0736] | −0.0096<br>[−0.0191, **+0.0001**] | −0.0017<br>[−0.0057, **+0.0025**] | 14 天为正 |

**random 阶段有两件必须同时读出的事，它们并不矛盾：**

1. **排序增量通过。** $\Delta$AP 是最小效应 0.005 的约 5.2 倍，CI 下界 0.0183。
2. **绝对概率门未通过。** `final_claim_decision.json` 中
   `absolute_probability_gate` 对 BL1 和 BL2 均为 `false`，
   `static_baseline_gate` 也是 `false`——两个模型的绝对概率健康都比冻结的 BL0 更差。
   通过的只有 `probability_saturation_gate`（没有大面积饱和）。

此外 random 阶段的 $\Delta$Log Loss 与 $\Delta$Brier 的 CI **跨 0**。
这允许说"概率损失点估计方向改善"，**不允许**说"已被统计确定改善"。

> 表中的 `4/4`、`17/17` 是逐日 $\Delta$AP 为正的天数，用于发现单日反向退化，
> **不能代替 CI**——它们不是 4 次或 17 次独立重训。

### 6.2 v011：只修概率刻度，不碰排序

random 目标域的正例率约 8.4%，远低于 standard 训练期的约 31%–32%。
冻结分数的排序可用，不等于它输出的 0.35 真代表 35% 概率。

**设计。** 目标域按时间切成 fit（8,731 行）→ selection（10,544 行）→ held-out（23,752 行）。
候选校准器只在 fit 拟合、在 selection 选择，held-out 完全不参与任何选择。
三个候选：M1 先验平移、M2 固定正斜率只拟合截距、M3 Platt 型双参数。
M3 的 selection Log Loss 仅比 M2 低 0.000016，在冻结的 tie 规则下选更简单的 **M2**。

对冻结分数 $s_i$，形式统一为 $\hat p_i=\sigma(a s_i + c)$，最终存档
$a=1.0169043468$、$c=-2.0952099481$。由于 $a>0$，任意 $s_i>s_j$ 仍得 $\hat p_i>\hat p_j$——
**排序不变是硬门，不是副产品**。

<a id="fig2"></a>

![v011 校准前后的可靠性曲线](figures/fig2_reliability_v011.png)

**图 3** 是这轮最有说服力的证据。校准前（橙色）整条曲线远低于对角线——
模型普遍高估；校准后（蓝色）贴合对角线。圆点面积正比于分箱样本量，
可以看出绝大部分数据落在低概率区，两条曲线右端的抖动来自极小分箱。

| held-out 指标（23,752 行 / 967 用户 / 2,063 正例） | 原始 BL2 | M2 校准后 | 差异 / 95% CI |
|---|---:|---:|---|
| AP | 0.1977 | 0.1977 | **0（排序精确不变）** |
| event-gAUC | 0.6236 | 0.6236 | **0（排序精确不变）** |
| Log Loss | 0.5121 | 0.2689 | −0.2431 [−0.2586, −0.2268] |
| Brier | 0.1700 | 0.0748 | −0.0952 [−0.1022, −0.0880] |
| ECE20 | 0.2813 | 0.0067 | — |
| 平均预测概率 | 0.3682 | 0.0823 | 真实正例率为 0.0869 |

**结论：**在这一 post-audit 目标域测试中，独立校准让概率可信得多，且完全不触碰排序。
它不改变 v010 的历史价值结论，也**不会**把 v010 的 random audit 变回 untouched。

### 6.3 v012：受 tether 约束的目标域适配

v011 只改概率映射，理论上不可能提高 AP。若目标域的特征—标签关系也变了，
就需要检验有限度重训练是否有增量。但小样本上自由重训会遗忘 sealed 模型、追逐噪声，
因此加 tether 把参数拉回冻结解：

$$\mathcal L_{\mathrm{v012}}=-\frac1n\sum_i\big[y_i\log\sigma(s_i)+(1-y_i)\log(1-\sigma(s_i))\big]+\frac{\tau}{2}\lVert\mathbf w-\mathbf w_{\mathrm{sealed}}\rVert_2^2 .$$

截距不受 tether（允许适应目标域基准率），之后再在独立段做概率校准——
这把"排序结构的适配"和"平均概率的修正"分开了。
三个候选全部通过 eligibility，按冻结规则选中 `C2_balanced`（$\eta=0.01$、100 steps、$\tau=0.001$）。

最终回放（12,399 行 / 857 用户 / 1,039 正例，真实正例率 0.0838）：

| 模型 | AP | event-gAUC | Log Loss | Brier | ECE20 | 平均 $\hat p$ |
|---|---:|---:|---:|---:|---:|---:|
| TARGET_BL0 | 0.0838 | 0.5000 | 0.2880 | 0.0768 | 0.0030 | 0.0808 |
| OLD_BL2 + v011 | 0.1879 | 0.6214 | 0.2639 | 0.0728 | 0.0066 | 0.0816 |
| NEW_BL1（适配后无历史） | 0.1765 | 0.6139 | 0.2693 | 0.0736 | 0.0069 | 0.0775 |
| **NEW_BL2 + v012 calibrator** | **0.2049** | **0.6455** | **0.2606** | **0.0721** | 0.0062 | 0.0797 |

两个关键的同目标行配对对比：

| 对比 | 它回答什么 | $\Delta$AP | $\Delta$Log Loss |
|---|---|---|---|
| `NEW_BL2 − OLD_BL2+v011` | 重训练相对旧候选还值不值 | +0.0170 [0.0053, 0.0313] | −0.0033 [−0.0051, −0.0017] |
| `NEW_BL2 − NEW_BL1` | **适配之后 H2 是否仍有增量** | +0.0285 [0.0152, 0.0418] | −0.0087 [−0.0114, −0.0061] |

全部必需门通过，科学状态 `retraining_adds_value`，
工程建议 `deploy_NEW_BL2_with_v012_calibrator_pending_new_data_confirmation`。

<a id="fig3"></a>

![v012 最终回放的逐日 ΔAP](figures/fig3_daily_delta_ap_v012.png)

**图 4 记录了一个汇总数字掩盖的事实。** `positive_history_AP_days: 3`（门槛 ≥2）是通过的门，
但逐日 $\Delta$AP 在三天内从 +0.0322 衰减到 +0.0041。适配窗口的最后一天是 04-29，
三个回放日距适配时点分别是 7、8、9 天。

两面都要说：

- **不能过度解读。**每天只有约 4,000 行、320–370 正例，单日 AP 噪声很大；
  逐日值**没有做 bootstrap，没有 CI**，三个点不足以拟合衰减率。
  池化的 +0.0170 [0.0053, 0.0313] 仍是该段主结论。
- **也不能忽略。**方向与目标域适配的机制预期一致：适配学到的是"适配窗口附近"的关系，
  距离越远越失效。它直接决定部署时的 **retrain 频率**。

因此新数据确认应包含**足够长的回放窗口**（不是 3 天），
并预注册"逐日增量对 time-since-adaptation 的回归"作为次要终点。

### 6.4 一个必须带上的限制

`cat_user`（用户 one-hot）在特征集内。v012 的适配在 760 个用户上更新了含用户维度的权重，
而最终回放评估的 857 个用户与之高度重叠。

这在时点上完全合法（无未来泄漏），但意味着 `NEW_BL2 − OLD_BL2+v011` 的增量中
**含有用户级适配成分**——新用户 / 冷启动用户不会获得同等收益。
相对干净的对照是 `NEW_BL2 − NEW_BL1 = +0.0285 [0.0152, 0.0418]`（两者被同样适配过）。

## 7. 可以说与不能说

<a id="7-1"></a>

### 7.1 为什么不能把三轮指标合并

v010 的三个阶段覆盖不同时间与曝光域；v011 / v012 是同一 random 域上的 post-audit 切分，
且如 [§2.2](#2-2) 所述**共享数据**。因此不存在一个"总置信区间"，
也不能说 v012 推翻或替代了 v010。正确的读法是逐条命题：

| 证据链 | 验证的命题 | 状态 |
|---|---|---|
| v010 Validation → sealed | H2 是否在两个连续 standard 时间窗稳定提高离线预测 | 支持 |
| v010 random audit | 冻结的 H2 排序增量能否迁移到 random 曝光 | 支持；绝对概率不可直接部署 |
| v011 | 目标域能否不改排序而修复概率刻度 | 支持（post-audit） |
| v012 | 受约束适配能否比旧 BL2+校准再加价值 | 支持（post-audit replay） |

### 7.2 对照表

| ✅ 可以说 | ❌ 不能说 |
|---|---|
| 冻结 GPU Adam 下，H2 严格用户历史相对同静态基线有稳定的离线排序增量 | 模型已证明线上观看时长、留存或商业指标提升 |
| 该增量在 standard 与 random exposure 审计中都出现 | random 覆盖任意策略、全平台候选池，或可做无假设精确 OPE |
| v011 校准在 post-audit 目标域修复概率质量且严格保序 | v011 是 untouched random audit 或全新的确认试验 |
| v012 在最终回放中同时提升排序与概率 | v012 已完成新数据确认，可无审批上线 |
| `NEW_BL2 + v012 calibrator` 是当前最强**工程候选** | Adam 之外的优化器同样稳健；原 SGD 已被证明失败或成功 |
| H2 是用户**总体**历史状态 | H2 证明用户喜欢某标签 / 作者 / 内容语义（需 H3 交互合同） |
| v013 已登记神经序列设计与 5-seed 门 | Gold、神经序列训练或新标签访问已获授权或完成 |

### 7.3 部署姿态

若做工程试运行，把 `NEW_BL2 + v012 calibrator` 当作**可回滚候选**：
保留 BL1 / BL0 回退路径，监控曝光域、历史深度、warm/cold video、duration-valid 状态、
AP 代理指标与概率健康，并按 [§6.3](#6-3) 的衰减迹象设定重训周期。

若做科学机制，另建 H3（用户 × 作者/标签/内容）增量合同，以当前 BL2 为固定基线；
**不能把 H2 的成功改写为内容偏好结论。**

## 8. 下一步

### 8.1 新数据确认：先认清它做不了什么

### 8.2 建议优先做的实验：BL1+ 画像列消融

当前 BL1 的用户侧信息只有 `cat_user`，`user_features_1k.csv` 的 30 列画像**完全没进模型**。
因此存在一个可被攻击的替代解释：v010 证明的可能是
"用户基准率的时变估计优于用户 ID 的静态记忆"，而不是"严格历史有独立价值"。

这个消融**不需要任何新的数据访问授权**——用 Gate 2B 的 Train-only rolling-origin 即可，
不触碰 Validation / sealed / random。代码与数据现成，GPU 约 1–2 小时。
真正的前置是一次特征可用性裁定：那 30 列的采集时点未逐列证明，
需先在 `configs/feature_availability_v002.yaml` 中判定哪些可作静态特征、哪些只能作诊断。

**建议排在 v013 神经序列之前**——v013 需先物化正式 Gold，前置很重；
这个消融约 2 天就能把 v010 的核心结论加固一档。
